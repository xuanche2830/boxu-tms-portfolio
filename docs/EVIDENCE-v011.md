# 运输凭证与交付复核

凭证位于单票运输页面，由当前票据授权决定上传、查看和下载范围。上传文件、填写复核结论均不会自动推进接单、发运、按件签收或关单，也不会因为存在待补要求而新增关单门槛。

## 本版范围

- 文件类型：PDF、PNG、JPG/JPEG；单件 1 字节至 2 MiB，每票最多 30 件。
- 凭证类型：签收回单、运输单据、货物照片、异常照片、其他凭证。
- 每件记录原始文件名、大小、SHA-256、上传账号与时间、材料说明；可关联整票或本票内一个运输单元。
- 企业负责人及获授权项目员工可以登记待补要求、记录材料复核通过或需补充的结论。每次复核保留历史，使用版本校验防止覆盖他人刚写的结论。
- 获授权货代可以查看当前票的待补要求、上传并下载材料；不能发起企业内部复核。撤销订单授权、改派或取消导致访问范围变化后，下载也重新检查权限。
- 本票获授权成员均可看到凭证、材料说明和复核结论。这里不保存仅内部可见的私密备注。
- 原文件保存后不覆盖、不删除。需要补充或更正时上传新文件，并在说明中交代关系。待补要求和复核是材料记录，不构成外部电子签名或承运商回传证明。

## 文件存储与下载

SQLite 数据库各自使用同名 `.attachments` 私有目录。例如工作库 `data/collaboration.sqlite` 对应 `data/collaboration.attachments`；演示库对应 `data/collaboration-demo.attachments`。独立测试数据库同样拥有自己的目录。PostgreSQL 使用 `data/private-evidence/postgresql-<主机/端口/库名摘要>`，不把连接密码写入路径。

磁盘文件名由服务生成的随机编号组成，用户上传的文件名不参与路径拼接。附件目录不通过静态路由公开；下载经过当前账号和订单授权验证，返回下载响应而非嵌入网页执行。读取时校验文件大小和 SHA-256。

本版检查扩展名与基本文件头、文件尾是否匹配，**不提供病毒扫描，也不声称完整解析或验证 PDF/图片内容**。没有自动识别签收信息、OCR、外部存储或承运商接口。

## 备份与恢复

迁移版本为 `0004_order_evidence`，新增凭证文件元数据、待补要求和复核记录三张表。原业务表内容不改写。

应用创建的便携备份同时包含表记录和全部已登记附件的实际字节。文件缺失、大小或摘要不一致时拒绝创建备份，不能用“备份成功”掩盖附件丢失。备份读取阶段再次检查文件清单、类型、大小和摘要。

恢复仅允许新的空数据库和空附件目录。在数据库事务内恢复记录，写入并校验附件后提交；常规写盘或提交异常会回滚记录并移除本次已经写入的文件，写文件自身失败也清理半文件。突然断电或进程被强制终止仍可能留下没有数据库引用的文件；再次恢复会因目标目录非空而拒绝覆盖，应保留现场并改用新的空目标。

`0002_query_indexes`（v0.9）和 `0003_import_batches`（v0.10）的原有便携备份仍可校验和恢复；新附件表按空表补齐，不伪造不存在的附件。新格式解压后的整体上限为 128 MiB；超限明确拒绝。若使用数据库原生备份，必须同时保存对应的私有附件目录，单独复制 SQLite 或 PostgreSQL 数据不足以恢复附件。

## 前端集成契约

```tsx
<EvidencePanel api={api} orderId={order.id} units={detail.units} internal={internal} />
```

`api` 沿用协同 JSON 请求帮助函数；下载由组件使用同源凭据请求二进制并生成浏览器下载。组件自身引入 `evidence.css`，不修改外层导航或业务状态表单。

主要接口均位于 `/api/collab/project-logistics/orders/{order_id}`：

| 接口 | 权限与用途 |
| --- | --- |
| `GET /evidence` | 已获本票授权；文件、待补要求、复核历史与能力 |
| `POST /evidence` | 已获本票授权；JSON Base64 上传，带 `command_id` 防重复提交 |
| `GET /evidence/{id}/download` | 每次重新检查本票授权，并校验文件字节 |
| `POST /evidence-requirements` | 企业内部且已获本票授权；待补类型、单件范围、说明 |
| `POST /evidence/{id}/reviews` | 企业内部且已获本票授权；`version`、结论、说明和 `command_id` |

## 专项验收

在仓库根目录运行 `python scripts/check.py evidence`。脚本创建独立临时数据库和随机本机端口，不操作工作服务。也支持设置仅限 `tms_acceptance_` 前缀测试库的 `TMS_ACCEPTANCE_DATABASE_URL`。

SQLite 专项验收通过 144 项；当前执行结果写入 `.test-runs/`，该目录不进入公开仓库。覆盖权限撤销、跨票限制、幂等、并发附件上限、材料复核历史、待补不阻止原业务关单、损坏/缺失文件拒绝、32 件附件备份恢复、恢复中途故障回滚、文件 fsync 失败清理、备份内层内容校验、旧备份兼容和进程重启持久化。先前本机还完成 PostgreSQL 专项验证；公开 CI 默认只运行 SQLite。
