# 界面决策记录

泊序按“每天看风险、按票推进、出问题能找到责任与依据”的操作节奏安排界面。截图分别见 `images/overview.jpg` 和 `images/evidence.jpg`。

| 高频动作 | 当前入口 | 处理依据 |
| --- | --- | --- |
| 查待办与异常 | 工作总览，六阶段与优先跟进 | 先让管理者看到需行动的票，再进入具体项目或委托 |
| 更新项目与发运需求 | 项目与需求 | 项目是需求与多票委托的共同背景 |
| 接单、发运、签收、复核 | 运输委托 → 单票页签 | 状态、下一步与凭证保留在同一票据上下文 |
| 维护伙伴与导入 | 业务资料 | 频率低于按票跟进 |
| 管理成员与备份 | 企业设置 | 只对负责人显示；新建成员在名册的下一层 |
| 查看自身身份和改密 | 侧栏底部个人账号 | 与企业管理员的成员管理分开 |

在 v0.12 的凭证页，“待补与复核”之后先展示已提交文件；文件存在时，上传区默认收起，需要补交时再展开。货代点击“为此要求上传”会自动展开、关联待补要求并聚焦文件选择。复核状态和历史在文件卡片上就近呈现。390 像素窄屏不产生页面整体横向溢出。

色彩沿用低饱和灰绿与深绿色主操作。数据数字使用对齐的字形，风险同时使用文字，操作支持可见焦点与忙碌/错误/空状态。以上是本轮针对页面的信息架构和交互处理；参考 Taste 与 Impeccable 的公开建议，但没有宣称完成其全部检查或真实用户可用性研究。
