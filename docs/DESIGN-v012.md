# 为什么这样安排页面

日常使用时，最先要知道的是哪些票需要处理；进入单票后，才需要看具体动作和材料。因此工作总览放待办与异常，运输详情放下一步操作。页面截图见 [工作总览](images/overview.jpg) 和 [凭证复核](images/evidence.jpg)。

| 要做的事 | 在哪里 | 为什么放这里 |
| --- | --- | --- |
| 找待办和异常 | 工作总览 | 先看哪些票要行动，再进入详情 |
| 更新项目与需求 | 项目与需求 | 一个项目可能关联多条需求、多票运输 |
| 接单、发运、签收和复核 | 运输委托 → 单票页面 | 状态、动作和材料都围绕同一票货 |
| 维护伙伴、处理导入 | 业务资料 | 这些任务不像运输跟进那样每天都要做 |
| 管理成员与备份 | 企业设置 | 只给负责人显示；新增成员放在名册的下一层 |
| 查看自己的身份、修改密码 | 侧栏底部的个人账号 | 和企业的成员管理分开 |

凭证页优先显示已经提交的文件。文件存在时，上传区默认收起；需要补交时再展开。货代点击“为此要求上传”，页面会展开上传区、关联对应的待补要求，并把焦点移到文件选择。复核结论和历史就在文件旁边，不用去另一页找。390 像素宽的手机视口下，页面整体没有横向溢出。

视觉上用了低饱和灰绿和深绿色操作按钮；数字对齐方便扫读，风险提示同时写明文字。按钮、加载、出错和空列表都有对应反馈。我参考了 Taste 和 Impeccable 的公开设计建议，重点调整了页面层级、信息密度和操作反馈；还没有做正式用户研究或完整无障碍审计。
